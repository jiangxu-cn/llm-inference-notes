## ③ 原理（8 min）

### 3.1 `sm_120` 不是型号，是"指令集版本"

RTX 5070 = Blackwell 架构 = **compute capability 12.0**，写作 `sm_120`。

类比 CPU：x86-64 是分代的（SSE → AVX2 → AVX-512）。给 AVX-512 编的二进制，拿到只支持 SSE 的 CPU 上直接崩。GPU 一模一样：**给 `sm_86`（RTX 3090）编的 kernel，不能直接跑在 `sm_120` 上。**

### 3.2 两级编译：PTX 和 SASS

```
CUDA C++  ──nvcc──▶  PTX  ──JIT / AOT──▶  SASS
（你写的）          （虚拟指令集）        （真实机器指令）
                    像"世界语"           像"各地方言"
```

- **AOT（提前编译）**：nvcc 版本够新 → 直接产出 sm_120 的 SASS。最快。
- **JIT（运行时编译）**：nvcc 太老 → 只产出 PTX，运行时驱动把它翻译成 SASS。**前提是驱动认得那个 PTX。**
- **两样都不行** → 报错 `no kernel image is available for execution on the device`。

### 3.3 为什么你现有环境一定跑不起来

| 你已有的 | 问题 | 判定 |
|---|---|---|
| `...\CUDA\v11.6` + cuDNN 8.6 (cuda11) | CUDA 11.6 最高只支持到 **sm_86**；而且那个目录里**连 `nvcc.exe` 都没有**，根本不是完整安装 | ❌ 对 5070 完全无用 |
| MinGW-w64 GCC 8.1.0 + OpenCV 4.5.2 | **`nvcc` 在 Windows 上只支持 MSVC (`cl.exe`)**，MinGW-GCC 不是受支持的宿主编译器 | ❌ 能写 OpenCV，**碰不了 CUDA** |
| 没有 Visual Studio | 上一条的前提不存在，`nvcc` 无从调用宿主编译器 | ❌ 硬阻塞 |
| 驱动 **610.88**（CUDA UMD 13.3） | 远超要求（WSL 需 ≥ 525） | ✅ **唯一合格项** |

> 这就是为什么 ① 里说 MinGW 那套用不上：**它和 CUDA 是两条互不相通的编译链路。**

### 3.4 两条路，选一条

| | A. Windows + VS2022 + CUDA | B. **WSL2 + Ubuntu + CUDA** |
|---|---|---|
| 要装什么 | VS2022（≈7 GB，且必须）+ CUDA + cuDNN | WSL2 + Ubuntu + CUDA（≤6 GB） |
| 宿主编译器 | MSVC（**你必须装**） | **gcc（Ubuntu 自带）** |
| 岗位相关性 | 一般 | **JD 明确要求 Linux 下 C++ 开发** ✅ |
| vLLM / nano-vLLM（W12–W13） | 基本跑不起来 | 原生支持 ✅ |
| ncu / nsys 性能分析 | 支持 | **官方支持** ✅（前提见 Step 5） |
| 额外好处 | 无 | 你已有的 Linux 经验直接复用 |

### 👉 选 B（WSL2）。三个理由

1. **你缺的是 MSVC，而 WSL 压根不需要它** —— 直接绕过最大的那个坑
2. **JD 要 Linux 环境下的 C++ 开发**，WSL 就是 Linux
3. W12–W13 的 vLLM / nano-vLLM 在 Windows 上极其折腾，在 WSL 里是原生

### Step 6 · 跑自检脚本

把下面存成 `env_check.py`，在 WSL 里跑：`python env_check.py`

```python
#!/usr/bin/env python3
"""L01 环境自检：5 项断言。全绿才算 L01 通过。"""
import shutil, subprocess, sys

HINTS = {
    "nvcc":       "→ nvcc 不在 PATH。执行 source ~/.bashrc，或检查 /usr/local/cuda-12.8/bin",
    "available":  "→ 装成 CPU 版了。必须带 --index-url .../whl/cu128",
    "kernel image": "→ wheel 的 CUDA < 12.8。重装 torch 并确认 cu128",
    "Ninja":      "→ pip install ninja",
    "arch":       "→ 在跑脚本前设置：export TORCH_CUDA_ARCH_LIST=12.0",
}
results = []

def check(name, fn):
    try:
        results.append((True, name, fn()))
    except Exception as e:
        msg = str(e)
        hint = next((v for k, v in HINTS.items() if k.lower() in msg.lower()), "")
        results.append((False, name, f"{msg} {hint}"))

def c1():                                   # ① 驱动认识显卡
    out = subprocess.run(
        ["nvidia-smi", "--query-gpu=name,memory.total,driver_version", "--format=csv,noheader"],
        capture_output=True, text=True, check=True).stdout.strip()
    name, mem, drv = (x.strip() for x in out.split(","))
    assert "NVIDIA" in name, f"显卡名异常: {name}"
    assert int(drv.split(".")[0]) >= 525, f"驱动 {drv} 过旧（WSL profiler 需 >= 525）"
    return f"{name} | {mem} | 驱动 {drv}"

def c2():                                   # ② nvcc 存在且 >= 12.8
    nvcc = shutil.which("nvcc")
    assert nvcc, "PATH 里没有 nvcc"
    out = subprocess.run([nvcc, "--version"], capture_output=True, text=True, check=True).stdout
    ver = [l for l in out.splitlines() if "release" in l][0].split("release")[1].split(",")[0].strip()
    assert tuple(int(x) for x in ver.split(".")[:2]) >= (12, 8), f"nvcc {ver} < 12.8，编不出 sm_120"
    return f"nvcc {ver}"

def c3():                                   # ③ PyTorch 是 CUDA 版且 cu >= 12.8
    import torch
    assert torch.cuda.is_available(), "torch.cuda.is_available() = False"
    assert torch.version.cuda, "torch.version.cuda 为空 → 装的是 CPU wheel"
    assert tuple(int(x) for x in torch.version.cuda.split(".")[:2]) >= (12, 8), \
        f"torch 的 CUDA {torch.version.cuda} < 12.8"
    return f"torch {torch.__version__} | CUDA {torch.version.cuda}"

def c4():                                   # ④ compute capability 是 Blackwell
    import torch
    cap = torch.cuda.get_device_capability()
    assert cap >= (12, 0), f"capability {cap}，期望 >= (12,0)"
    return f"{torch.cuda.get_device_name()} | sm_{cap[0]}{cap[1]}"

def c5():                                   # ⑤ 真跑一次矩阵乘 + 一个自定义 kernel
    import torch
    from torch.utils.cpp_extension import load_inline
    a, b = (torch.randn(1024, 1024, device="cuda") for _ in range(2))
    for _ in range(3):
        c = a @ b
    torch.cuda.synchronize()
    src = r'''
#include <torch/extension.h>
__global__ void k(const float* x, float* y, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) y[i] = x[i] * 2.0f + 1.0f;      // 边界检查：这是最重要的 CUDA 语法
}
torch::Tensor f(torch::Tensor x) {
    auto y = torch::empty_like(x);
    int n = x.numel();
    k<<<(n + 255) / 256, 256>>>(x.data_ptr<float>(), y.data_ptr<float>(), n);
    return y;
}
'''
    m = load_inline(name="l01_probe", cpp_sources="#include <torch/extension.h>\ntorch::Tensor f(torch::Tensor);",
                    cuda_sources=src, functions=["f"], verbose=False)
    x = torch.arange(8, dtype=torch.float32, device="cuda")
    y = m.f(x)
    assert torch.allclose(y, x * 2 + 1), f"自定义 kernel 结果错: {y}"
    return f"matmul OK | 自定义 kernel OK | 首元素 {c[0,0].item():.2f}"

check("① 驱动认识显卡", c1)
check("② nvcc >= 12.8", c2)
check("③ PyTorch >= cu128", c3)
check("④ compute capability >= (12,0)", c4)
check("⑤ 矩阵乘 + 自定义 kernel", c5)

print("=" * 64)
for ok, name, detail in results:
    print(f"{'✅' if ok else '❌'} {name}: {detail}")
print("=" * 64)
fails = sum(1 for ok, _, _ in results if not ok)
if fails:
    print(f"{fails} 项未通过 —— 不要往下走，把 ❌ 那几行发我")
    sys.exit(1)
print("🎉 L01 通过，环境可以支撑后面 14 周")
```

## ⑤ 语法与坑点（2 min）

| 语法 | 为什么这么写 | 最容易错在哪 |
|---|---|---|
| `k<<<grid, block>>>(...)` | 这是 **nvcc 的扩展语法**，不是标准 C++。三尖括号 = "在 GPU 上启动 grid 个 block、每个 block 有 block 个线程" | 写成两个尖括号会当成位移运算符，报一堆莫名其妙的错 |
| `if (i < n)` | GPU 上线程数是"向上取整"的，**最后一个 block 里必然有越界线程** | 漏了它就会踩到别人的内存，表现为"结果偶尔对偶尔错" |
| `x.data_ptr<float>()` | 拿张量的**裸指针**给 kernel 用。模板参数必须和 dtype 一致 | 传 `float` 却给 `half` 张量 → 结果全乱 |
| `torch.cuda.synchronize()` | CUDA 是**异步**的。不同步就计时，测到的是"提交任务的时间"而不是"算完的时间" | L02 整讲都在处理这个问题 |
| `subprocess.run(..., check=True)` | `check=True` 让非零退出码直接抛异常 | 不加就静默失败，你以为命令跑成功了 |
| `tensor.item()` | 把 0 维张量转成 Python 标量。**不调用它，显存里的数据不会被同步回主机** | 直接 f-string 打印会出来 `tensor(2., device='cuda:0')` |
| `torch.version.cuda` vs `torch.__version__` | 前者是"编译时用的 CUDA 版本"，后者是"PyTorch 版本" | 看 `__version__` 无法判断 wheel 是不是 cu128，必须看 `torch.version.cuda` |
